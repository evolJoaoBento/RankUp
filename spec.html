Python webservice, designed so new subjects and new features drop in without rewrites. v1 ships Philosophy, with an AI Socratic tutor (text) + practice tests / ranked ladder. Voice, evaluation booking and credentials are designed-for, not built.

1 · Architecture

Modular monolith, hexagonal

One deployable, split into bounded contexts with a strict dependency rule (outside-in):

interfacesFastAPI routers · SSE
↓depends on
application servicesuse-cases · orchestration · transactions
↓depends on
domainentities · events · ports (Protocol) — no I/O
↑implemented by
adaptersSQLAlchemy repos · Anthropic provider · Redis · clock · ids
Rule: the domain imports nothing outward. Adapters implement Protocol ports. This is what lets you swap Claude→another LLM, Postgres→graph DB, or extract a context into its own service — without touching domain logic.

Bounded contexts

identity catalog · Mastery Graph tutoring assessment progression metering evaluation 🔜 credentials 🔜 voice 🔜
2 · Extensibility

The 3 seams that make everything future-proof

Everything new is one of three plugin shapes. New work = implement an interface + register it; no edits to existing contexts.

1

Subject Packs

A subject is data, not code. A versioned YAML pack, validated, imported into Postgres. New subject = import a pack, zero deploy.

2

Activity plugins

Every surface (tutor, test, voice, debate) implements one interface and emits events. New feature = new Activity; the rest reacts to events.

3

Strategy ports

LLMProvider · Grader · MasteryModel. Swap/add models, or add a HumanGrader — same port.

    type: str  # "socratic_chat", "practice_test", ...
    async def start(self, ctx, params: dict) -> ActivityState: ...
    async def step(self, ctx, state, user_input) -> AsyncIterator[DomainEvent]: ...

2.3 — Strategy ports (swap implementations)

class LLMProvider(Protocol):
    async def stream(self, req) -> AsyncIterator[str]: ...
    async def parse(self, req, schema: type[T]) -> T: ...   # structured output

class Grader(Protocol):
    kind: str  # "mcq" | "ai_reasoning" | "human"
    async def grade(self, answer, question, rubric) -> Grade: ...

class MasteryModel(Protocol):
    def update(self, prior: float, outcome, difficulty: int) -> float: ...

v1: AnthropicProvider, MCQGrader + AIReasoningGrader, DecayBKTMastery. The future HumanGrader (evaluation) plugs into the same port.

6 · Progression

XP/ranks engine — config, not code

Ranks, thresholds and XP rules live in a ProgressionProfile (YAML/DB), referenced by a subject. Changing the scoring ≠ changing code.

# progression/profiles/standard.yaml
ranks: [ {Bronze:0}, {Silver:120}, {Gold:300}, {Diamond:560} ]
xp_rules:
  correct_base: 40
  streak_bonus_per: 5            # +5 * streak
  reasoning_multiplier: 1.0      # XP scales with reasoning_score → anti-offload
  wrong: 0
Activityemits event
→
AnswerGradedcorrect · reasoning_score
→
projectorapplies xp_rules
→
XpAwarded / RankUpappend + projection
Anti-offload baked in: XP scales with the grader's reasoning_score, not just correctness. Rebuild any projection by replaying events — audit-friendly, which matters because the product is trust.
7 · AI

Anthropic Claude integration

Per-task routing (cost-aware)

TaskModelNote
tutor_socraticclaude-haiku-4-5cheap, high-volume
grade_reasoningclaude-haiku-4-5structured output
generate_questionclaude-sonnet-4-6quality matters
voice / deep reasoningsonnet / opus 🔜later phase
  • Streaming tutor replies over SSE (client.messages.stream).
  • Structured outputs for grading (messages.parse + output_config.format) → typed Grade, no fragile parsing.
  • Prompt caching: system prompt + concept context with cache_control:{type:"ephemeral"} → stable prefix at ~0.1× cost across a session.
  • Metering: every call records a usage_event (tokens→micro-EUR); quota blocks free-tier users before the call.
class AnthropicProvider(LLMProvider):
    async def stream(self, req):
        async with self._client.messages.stream(
            model=self._router[req.task], max_tokens=1024,
            system=req.system_blocks,        # carry cache_control
            messages=req.messages) as s:
            async for text in s.text_stream: yield text
        await self._meter(req, await s.get_final_message())

    async def parse(self, req, schema):
        r = await self._client.messages.parse(
            model=self._router[req.task], max_tokens=1024, messages=req.messages,
            output_config={"format": pydantic_format(schema)})
        return r.parsed_output

9 · Auth

AuthN / AuthZ

  • JWT access (~15 min) + rotating refresh (hashed, stored). argon2id hashing.
  • RBAC via dependency: require_role("admin"), current_user. v1: student, admin (teacher arrives with evaluation).
  • Per-route + per-user rate limits in Redis. Ownership checks in services (a user reads only their own sessions).
  • Pluggable to OAuth/Clerk later — auth is a deps.current_user provider, swapped without touching routers.

12 · Build

Build order (v1)

Skeleton — app factory, config, DB session, Alembic, identity (auth + RBAC), /healthz.
catalog — pack schema (Pydantic) + loader + Philosophy pack + graph endpoints + closure build.
metering — usage_event + quota + price table (wire to a fake provider first).
tutoring — SocraticChatActivity + AnthropicProvider (stream) + SSE endpoint + prompt assembly from the pack.
assessment — PracticeTestActivity + MCQ/AIReasoning graders + answer endpoint (idempotent).
progression — events + projector + ProgressionProfile + progress/leaderboard endpoints.
Hardening — tests (testcontainers), observability, rate limits, Docker, CI.
